## 特征的实际差异

- shy：34项动态变量的最近值、6小时实测均值/极值/变化量、缺失与测量间隔/次数、背景变量及缺失标记；6项全缺失特征删除后312列。统计基于真实观测；最近值允许恰好6小时旧的测量。
- main基础208维：34变量×6统计（窗口末次值、均值、标准差、变化量、距末次观测、当前缺失），加年龄、性别、HospAdmTime、ICULOS；窗口仅当前及前5小时。
- main增强201维：7项生命体征及两个时长变量的5/11小时均值、极值、中位数、方差、分位数；累计平方能量、能量熵、平均差分、前缀长度及末次值。该模块在历史前缀内持续向前填充；基础模块仍保留6小时窗口限制。
- main缺失154维：观测/缺失段的均值、方差、累计观测比例等，以及整体覆盖度的0–4小时滞后。部分特征为相关或确定性变换，维度更多不等于独立生理信息更多。
- main不使用Unit1/Unit2；其410维recent对照去除ICULOS/HospAdmTime及无界累计历史，以局部6/12小时统计和真实测量斜率为主。
- main特征输出保留NaN，没有在此阶段做全体数据插补、标准化或裁剪。后续训练如何处理缺失、类别权重、模型参数、早停与阈值，当前发布代码不能核实。

ICULOS、prefix_length、累计能量可能反复编码住院时长；当前时长是当时可见信息，不应直接称为泄漏。但完整记录任务可能奖励对长记录/发病后持续高风险的识别。需要在相同预警任务和划分中消融验证。

## 核验与边界

- 4个预处理单元测试通过；实际原始数值缓存上逐人核查入选资格、患者划分和CV名单。
- 18份真实记录的563/410两套特征均通过多个前缀长度的逐元素一致性检查；标签列被特征接口拒绝，未见明显未来填充或标签直接入模。
- 完整构建/Parquet集成测试未执行：现有项目环境缺少pyarrow，main声明的依赖版本也与当前环境不同。这是环境限制，不是特征代码失败的证据。
- main README publication status及feature_validation.json明确：此次发布不重训模型，训练/评测脚本未发布。因此当前不能复核朋友具体高分或归因于某个特征。

先固定同一份患者划分、同一种训练/评价小时范围、同一模型配置及阈值规则，再比较312与563/410特征。若兼顾原早期预警问题和竞赛复现，可分别报告发病前预警与完整记录识别；不要直接交叉比较分数。可用2×2对照拆分“312/563特征”与“发病前/完整记录任务”的影响，所有选择在训练患者内部完成。
