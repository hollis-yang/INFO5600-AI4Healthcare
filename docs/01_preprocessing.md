# 01 · 数据预处理与患者划分

本阶段将原始患者文件转为可追溯的患者清单，不训练模型。运行入口为 `sepsis_pipeline/preprocess.py`。

## 固定的数据口径

采用 `SEPSIS_FULL_RECORD_V2`：沿用既定筛选患者，纳入每人的全部小时，标签直接取原始 `SepsisLabel`。包含发病后和记录结尾，长记录患者在逐小时指标中贡献更多小时。数据标签已提前 6 小时标记，不能再移动一次。

“完整记录”指已纳入患者的完整记录；既定患者筛选条件仍保留。因此，筛选仍要求至少存在一个原方案可评估窗口，但不会用该窗口截断入选患者的记录。

## 处理顺序

1. 按 A/B 院、文件名排序，校验 41 列的名称、顺序和文件 SHA-256；保留原文件字节。
2. 两院共同检查完全相同文件的 SHA-256，后出现的重复记录排除。
3. 依次排除：空记录、小时不连续、标签非法或从 1 回到 0、首条年龄缺失或小于 18、年龄/性别前后矛盾、首条标签已阳性、推算发病点超出记录、没有完整预测窗口。
4. 仅为复现既定队列，发病点定义为首次阳性标签对应小时 +6；该值只是审计元数据，禁止作为输入特征。
5. 入选患者保留全部小时及原始标签。缺失值继续保留为 NaN；特征阶段只允许当前及过去信息。
6. 各院独立按患者是否发病分层：先 70%/30%，再将 30% 平分为验证/测试，种子均为 42。合并各院对应集合。
7. 仅训练集做患者级三折，按“医院×是否发病”分层，种子为 2026。验证/测试 `cv_fold=-1`。

## 运行

```bash
python -m pip install -r requirements.txt
python -m sepsis_pipeline.preprocess --data data --output outputs/preprocessing
python -m unittest discover -s tests -v
```

输出目录必须不存在，避免覆盖已冻结的患者划分。重复实验请使用新目录。

| 输出 | 内容 |
| --- | --- |
| `patient_splits.parquet` | 每位入选患者的相对路径、SHA-256、医院、事件状态、完整时长、集合与折号 |
| `excluded_patients.csv` | 每位排除患者及首个排除原因 |
| `cohort_counts.csv` | 按集合/医院汇总的患者数、事件患者数、完整小时、阳性小时 |
| `cv_fold_counts.csv` | 训练折的医院和事件分布 |
| `preprocessing_report.json` | 队列口径、种子、审计统计和患者清单校验值 |

## 本版本应复现的数量

原始 40,336 人，纳入 39,874 人，排除 462 人。完整记录合计 1,545,966 小时。

| 集合 | A 院患者 | B 院患者 | 合计患者 | 事件患者 | 完整小时 | 阳性小时 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 训练 | 14,091 | 13,820 | 27,911 | 1,742 | 1,081,518 | 16,952 |
| 验证 | 3,020 | 2,961 | 5,981 | 374 | 233,738 | 3,630 |
| 测试 | 3,020 | 2,962 | 5,982 | 374 | 230,710 | 3,630 |

这是两家已知医院内部的患者留出划分，不能称为跨医院外部验证。源数据此前已用于开发；重新固定划分不使其成为未接触的外部队列。

后续统一以完整记录逐小时 AUROC 为主指标；验证集仅按完整记录 Utility 最大化选择每个模型的一个阈值。测试集不参与模型或阈值选择。
